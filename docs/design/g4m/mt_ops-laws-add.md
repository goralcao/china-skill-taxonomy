## 三、仿真 spec

**机制**：三张数字卡换位置，和从头到尾不变，变的只有中间两步。

| 案例 | 三个数 | 原顺序第一步 | 换完第一步 |
| --- | --- | --- | --- |
| 三个班捐书 | 186、97、214 | 186 + 97 = 283（进位） | 186 + 214 = 400（整百） |
| 三场义卖收款 | 47、386、53 | 47 + 386 = 433（进位） | 47 + 53 = 100（整百） |

- 卡槽 `SIM_CARD_W=160, SIM_CARD_H=110, y=96`，横坐标 `[70, 285, 500]`
- 右侧固定面板「和」：直接取原始三个数之和，**不随换位变化**，用来钉住不变量
- 第一步的括号线：`n0 + n1` 能被 100 整除时变绿并标「凑成整百，不用进位」，否则灰色并标「个位 x + y，要进位」
- 操作：点一张卡选中（橙框 + 「已选中，再点一张」），再点另一张互换；`simHint` 算出该换哪两张；`simCase` 换题；`simReset` 复原
- Canvas 点击按 `getBoundingClientRect` 换算到 880×360 逻辑坐标命中卡片

## 四、易错点

1. **把交换律用到减法上**：40 − 15 写成 15 − 40，答案连正负都变了。
2. **搬家搬错数**：97 挪过去抄成 79，和差 18。
3. **只换不凑**：换了位置还是 186 + 97 先算，白忙一场。
4. **硬凑整把数拆散**：97 想凑 100 就从 214 里借 3，三个数变四个数，越算越乱。

## 五、验收

- 12 页零横溢，14 题四测验全对（`pre [0,1,0]`、`mid1 [1,0,1]`、`mid2 [0,2,0]`、`post [0,1,0,1,0]`）
- 连线 16 个可点元素
- 仿真读数：`186 + 97 + 214` → 换第 2、3 张 → `186 + 214 + 97`；`simCase` → `47 + 386 + 53`；两案例和分别 497 / 486
- 画布点击实测：点 1、2 张 → `97 + 186 + 214`，交换次数 1，控制台 0 错误
- V4 首卡 `opacity = 1`
