# 课件层计划（Courseware）

> 状态：草案 · 2026-10-27 · 对应 v0.23 起
> 目标读者：维护者、贡献者、想要复用这套结构的团队

## 一、为什么加这一层

图谱回答「学什么、先学什么」，教学研究回答「怎么教」。这两层服务的是家长、老师和开发者，缺一个角色：**学生自己**。

学生拿着一句「掌握证据」没法自学。他需要的是：一个具体情境、一步步的操作、做错时的反馈、以及「我学完了」的确认。

所以第三层的形态不是文章，是**可交互、可完成、可回写**的课件。

## 二、边界

做：

- 每个课件绑定唯一 `topicId`，从图谱可直达
- 单文件 HTML，离线可用，无外部依赖、无追踪
- 完成状态回写图谱，参与「已掌握」判定
- 覆盖优先做「适合交互」的知识点，不强求全量

不做：

- 不做视频（编解码、TTS、渲染管线成本高，与静态站定位冲突）
- 不复制教材原题原文（自编或改编，出处只标课标与教材位置）
- 不做账号体系与云端同步（本地存储 + 导出，够用）
- 不做「AI 自动出题 + 自动判卷」的全自动闭环（正确性无法保证）

## 三、架构：四层与一个闭环

```
图谱层    1268 主题 · 1635 条先修 · 课标/教材锚点        （已有）
   ↓ 点击知识点
教学层    1268 条教学研究：教法 / 活动 / 诊断           （已有）
   ↓ 渲染
课件层    courses/<topicId>/  10~15 分钟交互页          （新增）
   ↓ 完成事件
反馈层    完成记录 → 掌握标记 → 缺口诊断 → 推荐下一篇     （新增）
   ↖______________________________________|
```

闭环成立的条件是「完成事件」可被图谱读到。做法：课件与图谱同源（同一域名/同一 `file://` 目录），课件结束时写 `localStorage["stx.course.<topicId>"] = {done, score, at}`，图谱读取后把该主题标为「有课件·已完成」，并与手动标记的「已掌握」分开展示。

## 四、数据模型

### 目录

```
courses/
  mt_math-3-time/
    index.html      # 自包含课件（内联 CSS/JS/SVG）
    meta.json       # 元数据
data/courses.json   # 构建产物：索引（不含正文）
schema/course.schema.json
```

正文不进入 `data/`，索引只保留元数据，避免把 4MB 的 `data.js` 继续撑大。

### meta.json

```json
{
  "topicId": "mt_math-3-time",
  "title": "时、分、秒：一小时为什么是 60 分钟",
  "template": "explain",
  "duration": 12,
  "interactions": 4,
  "grade": 3,
  "subject": "数学",
  "standards": ["math-2022:S1:NA:QTY"],
  "prerequisites": ["mt_math-2-clock"],
  "next": ["mt_math-3-date"],
  "objectives": ["能读出钟面上的时刻", "能换算时、分、秒"],
  "status": "reviewed",
  "author": "goral.cao",
  "license": "CC-BY-SA-4.0",
  "version": "1.0.0",
  "updatedAt": "2026-10-27"
}
```

字段约束：

| 字段 | 规则 |
|---|---|
| `topicId` | 必须存在于 `topics.json` |
| `template` | `explain` / `drill` / `explore` / `review` |
| `duration` | 5~25（分钟），与实际交互量匹配 |
| `interactions` | ≥2，且与 HTML 中 `data-step` 数量一致 |
| `standards` | 必须属于该主题已挂的课标编号 |
| `status` | `draft` / `reviewed` / `deprecated`，只有 `reviewed` 在图谱上显示入口 |
| `license` | 固定 `CC-BY-SA-4.0`（与内容层一致） |

### 索引 courses.json

```json
{
  "version": "v0.23.0",
  "schemaVersion": 1,
  "generatedAt": "2026-10-27",
  "counts": { "total": 12, "byTemplate": { "explain": 8, "drill": 4 }, "byStatus": { "reviewed": 10, "draft": 2 } },
  "courses": [ { ...meta.json, "path": "courses/mt_math-3-time/" } ]
}
```

## 五、教学结构 × 呈现方式

模板回答「怎么教」，呈现器回答「怎么画」。两件事正交：同样是「练习」，加减法要竖式、单词拼写要填空；同样是「讲解」，钟表要转指针、面积要铺方格。

只看教学结构会出现一个具体问题：**所有课件都长成「一段话 + 一个输入框」**。竖式写成了横式，几何只剩文字描述——这恰恰是学生最难靠文字理解的部分。

### 5.1 教学结构（template）

| 模板 | 适用 | 页面结构 | 典型交互 |
|---|---|---|---|
| explain | 概念首次出现 | 情境 → 分步讲解（3~5 步）→ 中途检查 → 小结 | 点击揭示、拖拽排序、单选中途问 |
| drill | 计算、语法、拼写 | 示例 1 个 → 变式 4~6 题 → 错因反馈 → 复盘 | 输入判分、选项判分、逐步提示 |
| explore | 几何、物理、地理 | 参数面板 → 实时图形 → 观察任务 → 归纳 | 滑杆、拖点、切换条件 |
| review | 单元复习、错题 | 知识卡 → 连线/归类 → 综合题 | 匹配、分类、排序 |

### 5.2 呈现方式（renderer）

`templates/renderers.js` 里每个 `CR.xxx()` 返回一个控制器，负责画和动，不负责教学顺序。

| renderer | 画什么 | 适用主题 | 关键能力 |
|---|---|---|---|
| `vertical` | 竖式 | 加减乘除、小数竖式、除法竖式 | 数位对齐、进位/借位标记、逐位揭示 |
| `geometry` | 几何图形 | 面积、周长、图形变换、割补 | 方格铺满计数、剪拼动画、尺寸标注 |
| `solid` | 立体图形 | 长方体、正方体、棱柱、展开图 | 手写投影、拖动旋转、按组高亮面/棱/顶点、摊平成展开图 |
| `pyramid` | 棱锥与空间角 | 线面角、二面角 | 3D 投影、作射影或垂线、标夹角并给出度数 |
| `division` | 除法竖式 | 除数是一位数/两位数 | 试商、乘、减、落四步逐步揭示 |
| `molecule` | 分子与原子 | 质量守恒、化学反应 | 断键、原子位移、成键、原子清点 |
| `calendar` | 年历 | 年月日、平年闰年 | 12 个月按天数分色、二月可切年份 |
| `decimal` | 小数条 | 小数意义、一位小数加减 | 十格条涂格、逐条点亮 |
| `table` | 复式统计表 | 两组数据对比 | 两行数据并排、逐行高亮、自动合计 |
| `compass` | 方向与路线 | 八方向、描述路线 | 罗盘 + 地图、路线动画 |
| `law` | 运算律 | 加法/乘法交换律、结合律、乘法分配律 | 上下两式对照、数字滑动换位、括号移动、分配律面积模型分块 |
| `triangle` | 三角形 | 三角形的分类、内角和、三边关系 | 由角度反推形状、撕角拼平角动画、三边逐条验算并成图 |
| `counter` | 数位顺序表 | 大数的认识、十进制进率 | 亿/万/个三级分级、满十进一动画逐级上跳 |
| `angle` | 量角器 | 角的度量与分类 | 中心对顶点三步法、可拖动的边、实时读数与分类 |
| `quad` | 平行四边形与梯形 | 四边形按平行组数分类 | 成对箭头标平行、逐个高亮、梯形的高 |
| `decGrid` | 百格图 | 小数的意义与性质 | 1 格 0.01、一列 0.1；双图对比证明 0.3=0.30 |
| `mult2` | 多位数乘法竖式 | 三位数乘两位数 | 两段部分积逐步揭示，十位一行向左错一位并标注实际值 |
| `chart` | 条形/折线统计图 | 统计单元 | 纵轴「一格表示几」、条形从基线生长、折线描点连线看趋势 |
| `mean` | 平均数（移多补少） | 统计单元 | 多余部分移走、缺口补上，条形拉平到平均线 |
| `polyArea` | 多边形面积割补 | 面积公式推导 | 沿高剪开平移、两个三角形/梯形旋转 180° 拼合 |
| `factorGrid` | 摆方格找因数 | 因数与倍数 | 摆出所有长方形，因数成对列出 |
| `fracMeaning` | 分数的意义 | 平均分、分数单位、单位「1」、分数与除法 | 可拖滑块改份数、按住拖动涂色、一盒苹果换整体、3÷4 分饼动画 |
| `fracOps` | 分数加减条 | 同分母/异分母分数加减 | 三条分数条对照，异分母「重分」演示通分 |
| `volume` | 等距堆方块 | 体积与容积单位 | 手写等距投影，小正方体逐层铺满长方体 |
| `pairs` | 数对网格 | 位置（数对） | 列行虚线定位，点格子直接报数对 |
| `treePlant` | 植树间隔 | 植树问题 | 间隔数可拖、三种栽法切换，棵数差 ±1 |
| `symmetry` | 对称补全 | 轴对称 | 对称点可拖、距离实时标注、逐点补全另一半 |
| `fracReduce` | 重分分数条 | 约分、通分、分数基本性质 | 同除/同乘「重分」分数条，涂色部分不变 |
| `spinner` | 随机转盘 | 可能性 | 真随机旋转记账，频率靠近区域占比 |
| `decMult` | 小数点定位 | 小数乘法 | 先按整数算，数小数位点小数点 |
| `decDiv` | 商不变转化 | 小数除法 | 除数变整数，×10 箭头演示同步移位 |
| `fracDiv` | 切饼分份 | 分数与除法 | 每块饼真切开、真分掉，3÷4=3/4 有了来历；假分数化带分数 |
| `balance` | 天平找次品 | 找次品 | 分三份→称量→嫌疑缩到 1/3，天平真的会倾斜 |
| `callTree` | 通话树 | 打电话 | 每分钟长一层，1→2→4→8→16 翻倍看得见 |
| `clock` | 钟面 | 时、分、秒 | 三针联动、分针拖拽、指针高亮 |
| `numberline` | 数轴 | 正负数、分数、小数、时间轴 | 区间高亮、可拖手柄 |
| `coords` | 坐标系 | 一次函数、抛物线、统计 | 网格、曲线描边动画、散点 |
| `sim` | 物理模拟 | 力、运动、动量 | 参数化场景、实时读数（待抽公共实现） |
| `chart` | 统计图 | 条形、折线、扇形 | 数据驱动、切换维度 |
| `diagram` | 示意图 | 生物结构、地理剖面、历史地图 | 分区高亮、热点标注 |
| `equation` | 式与方程式 | 化学方程式配平、公式推导 | 分步变形、系数联动 |
| `text` | 纯文字 | 观点、史料、政策条文 | 分步高亮（兜底） |

调用方式：

```js
var v = CR.vertical(host, { a: 345, b: 278, op: '+' });
v.reveal(3);       // 从右往左揭示 3 位答案
v.carries(true);   // 显示进位小 1
```

`meta.json` 用 `renderer` 字段声明用了哪个，校验器会检查白名单，以及页面里是否真的调用了 `CR.<renderer>(`。

### 5.3 对应关系（哪些主题用哪个）

| 主题类型 | 推荐组合 | 例子 |
|---|---|---|
| 四则运算 | drill + vertical | 万以内的加减法、多位数乘一位数、小数除法 |
| 几何度量 | explain + geometry | 长方形面积、平行四边形面积、圆的周长 |
| 时间与单位 | explain + clock / numberline | 时分秒、24 时计时法、千米与吨 |
| 数与代数 | explain + numberline | 负数、分数的意义、小数的性质 |
| 函数与图像 | explore + coords | 一次函数、反比例函数、二次函数 |
| 物理规律 | explore + sim | 动量守恒、欧姆定律、光的反射 |
| 语言类 | drill + text | 时态、词汇、病句修改 |
| 文科理解 | explain + diagram | 细胞结构、气候类型、历史进程 |

### 5.4 共享与内联

源文件引用仓库级的样式与呈现器：

```html
<link rel="stylesheet" href="../../templates/base.css">
<script src="../../templates/renderers.js"></script>
```

构建时 `sync_courses_to_viz()` 会把这两行替换成内联内容，产物仍然是**单文件、零外链**。校验器两头都管：源文件只允许引用 `templates/` 下这两个文件，产物里不允许残留任何 `src=` / `href=`。

这样同一个呈现器只维护一份，1268 个课件不必各自复制一套 SVG 代码。

### 5.5 共同要求

- 每步一个 `data-step` 容器，支持键盘 `←/→` 切换
- 至少 1 个「易错点」提示，内容取自教学研究的 `assess.errors`
- 至少 1 个迁移题，取自 `assess.nextMoves`
- 结束页显示：用时、答对题数、掌握建议（对应 `assess.levels`）
- 尊重 `prefers-reduced-motion`：动画降级为直接呈现终态

## 六、生产流水线

### 脚手架

```bash
node scripts/new-course.mjs mt_math-3-time --template=explain
```

自动完成：

1. 从 `data/topics.json` 取主题名称、描述、掌握证据、课标、教材位置
2. 从 `data/teaching-research.json` 取 `pedagogy`、`activities`、`assess`
3. 生成 `courses/<topicId>/meta.json` 与 `index.html` 骨架，内容已填入可编辑的占位
4. 打印本地预览命令

### 人工改写

脚手架产出的是「结构完整的草稿」，需要人做的三件事：

- 把 `pedagogy` 的书面语改成对学生说的话（第二人称、短句）
- 为每个 `activity` 补一个可交互的动作（点、拖、输、选）
- 核对数字与事实（数学复算、文科核人名年代、英语核拼写）

### 校验

```bash
node scripts/validate-courses.mjs
```

规则见第七节。CI 中与 `validate.mjs` 并列执行。

### 批量

按「册」推进。一册 25~35 个知识点，两周一个批次：

```
周一  生成该册全部草稿（脚手架批量模式）
周二~周四  人工改写 + 抽检
周五  校验 + 预览 + 合并
下周一  随 patch release 发布
```

## 七、质量门槛

`validate-courses.mjs` 的检查项：

| # | 检查 | 失败后果 |
|---|---|---|
| 1 | `meta.json` 存在且字段齐全 | 阻断 |
| 2 | `topicId` 能在 `topics.json` 找到 | 阻断 |
| 3 | `template` 取值合法 | 阻断 |
| 4 | `standards` ⊆ 该主题的 `standards` | 阻断 |
| 5 | `interactions` 与 HTML 的 `data-step` 数一致 | 阻断 |
| 6 | HTML 无 `<script src=`、`<link href=` 外链 | 阻断 |
| 7 | 单文件 < 300KB | 阻断 |
| 8 | 含 `<html lang="zh-CN">`、`<title>`、`viewport` | 阻断 |
| 9 | 有 `data-step` 与「上一页/下一页」键盘处理 | 警告 |
| 10 | 有至少 1 处 `.pitfall`（易错点） | 警告 |
| 11 | `duration` 与 `interactions` 比例在 3~6 分钟/交互 | 警告 |
| 12 | 数学类：内联 `window.__ANSWERS` 中的数值能被 `eval` 复算通过 | 警告 |

正确性策略（按学科）：

- 数学：题干与答案写进 `window.__ANSWERS`，校验脚本用 Node 复算（后续接 sympy 做符号验算）
- 物理/化学：公式与单位显式校验（量纲表）
- 语文/历史：`window.__FACTS` 列出人名、年代、事件，人工核对清单
- 英语：`window.__WORDS` 词表校验拼写

## 八、闭环与推荐

### 完成回写

课件结束页调用：

```js
localStorage.setItem('stx.course.' + TOPIC_ID,
  JSON.stringify({ done: true, score: 0.8, at: Date.now(), v: '1.0.0' }));
```

图谱 `viz/index.html` 读取同前缀的键，在节点上叠加一个「小圆点」标记（区别于手动掌握的「金色环」）。

### 推荐下一篇

优先级：

1. 当前主题 `unlocks` 中尚未完成的、且课件存在的
2. 同册内 `next` 字段指定的
3. 同领域内 `centrality` 最高且未完成的

推荐卡片出现在课件结束页和图谱详情面板两处。

### 课件与图谱的双向延伸

课件不是终点页，是图谱上的一个入口。构建时 `build_graph_context()` 会把该主题的图谱邻域写成 `window.__GRAPH` 注入每个课件，前端用两个共享组件消费：

**页首位置条** `CR.graphNav()` —— 一行说清「这课在图上的哪儿」：

```
前置 100以内笔算加减法 · 万以内数的认识 → 本课 万以内的加法和减法 → 解锁 三位数乘两位数 · 运算律
```

每个名字都能点回图谱对应节点。学生（或家长）看课件前就知道前置是什么，卡住时知道该退回去补哪一课。

**页尾延伸** `CR.extend()` —— 三块：

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 回去补一补 | 先修主题 + 每条依赖边的理由 | `dependencies.reason` |
| 接着学 | 解锁主题，优先有课件的 | `unlocks` + `courses` 状态 |
| 这一课在图谱里是什么 | 领域、学段、年级、课标编号、教材册次与单元 | `topics` + `textbooks` |

教材引用会翻译成人话：`pep-math:3b:u5` → 「人教版数学 · 3 年级下 第 5 单元」。

**图谱侧**：详情面板显示「打开课件（N 分钟）」，完成后节点右上角出现绿点；工具栏新增「▶ 有课件 N」开关，一键筛出所有能动手的主题，视图自动贴合到这几个点。

这一层不需要手写：课件只要声明 `topicId`，邻域数据由构建脚本从 `dependencies.json` 和 `textbooks.json` 现算，主题改了依赖，课件跟着改。

## 九、分发

- **GitHub Pages**：`courses/` 与 `viz/` 一起部署，自带 gzip，解决现在 4.1MB 未压缩的问题
- **深链**：`?t=<topicId>&course=1` 直接打开课件；课件结束可回跳图谱
- **学期包**：`courses/packs/grade-3-math-a.json` 列出该册课件顺序，供老师整册使用
- **打印**：每个课件提供 `?print=1` 的纯文本讲义视图（复用 `printArea` 逻辑）

## 十一、度量与节奏

`scripts/health.mjs` 每周输出：

数字变化自动开 issue（`health` 标签），避免「想不起来做什么」。

固定节奏：

- 每周一：health 报告
- 每周三：issue triage（内容 / bug / 结构三类）
- 每两周：patch release（课件包 + 修复）
- 每月：minor release（功能）
- 每季度：结构评审（schema 变更需迁移脚本）

## 十二、风险与取舍

| 风险 | 应对 |
|---|---|
| AI 生成内容出错 | 数学复算、文科事实清单、人工抽检 20% |
| 1268 个做不完 | 按册推进，公开覆盖率，不承诺全量 |
| 模板僵化 | 模板与内容分离，模板升级可批量重渲染 |
| 维护成本上升 | 课件是静态文件，无服务端；CI 只做静态校验 |
| 与教材版权冲突 | 不用原题原文，题目自编/改编，出处只标位置 |
| 完成标记失真 | 「课件完成」与「已掌握」分开显示，不自动等同 |

## 十三、决策记录

- **为什么单文件而不是构建式框架**：与 `viz/` 保持一致，`file://` 可直接打开，贡献者不需要装依赖；代价是模板复用靠复制而非 import，用脚手架缓解。
- **为什么元数据与正文分离**：索引要进 `data.js`，正文不能进；分离后索引可随图谱一起加载。
- **为什么不做视频**：链路长、成本高、难校验，且与「离线可用」冲突。
- **为什么先做三年级数学**：用户起点明确、交互性强、家长需求集中，适合验证模板；高中理科第二优先（3D/符号计算价值高但成本也高）。

### 引擎化：从「手写页面」到「一份 JSON」

前 4 个课件是手写的。写到第 5 个时问题很明显：导航、判分、结算、图谱延伸四段代码每份都要复制，改一处要改四遍，一册 30 个更不可能维护。

所以 P2 先做引擎：

- `templates/engine.js` 接管页面骨架与全部通用逻辑
- 课件只剩 `content.json`（steps 数组）+ 一个 16 行的薄壳 `index.html`
- 41 种步骤类型：`intro` / `text` / `vertical` / `geometry` / `solid` / `pyramid` / `division` / `mult2` / `molecule` / `calendar` / `decimal` / `table` / `compass` / `law` / `triangle` / `counter` / `angle` / `quad` / `decGrid` / `chart` / `mean` / `polyArea` / `factorGrid` / `fracMeaning` / `fracOps` / `fracReduce` / `spinner` / `decMult` / `decDiv` / `volume` / `pairs` / `treePlant` / `symmetry` / `numberline` / `clock` / `fracDiv` / `balance` / `callTree` / `quiz` / `choice` / `summary`
- 构建时把 content.json、engine.js、renderers.js、base.css 全部内联，产物仍是单文件

写一节课从「复制 300 行 HTML」变成「写 60 行 JSON」。

### 用技能生成课件

`skills/k12-courseware/` 把四件事串成一条流程，避免「先写页面再想教学」：

| 步骤 | 借自 | 产出 |
|---|---|---|
| 0 图谱定位 | 本项目 | 前置、解锁、课标、年级 |
| 1 EVAL | math-viz-kit V1 | 一句话：核心动态关系，或「不值得做」 |
| 2 教学设计 | k12-teacher-skills | 目标 3 条、前测、主线、检测题与迷思 |
| 3 认知动作 | V7 | `cognitiveAction` 七选一 + renderer |
| 4 排步骤 | V3/V4/V5/V8 | 8–10 步 `content.json` |
| 5 数值内核 | edulab | 算式、进位、答案先算再写 |
| 6 校验 | 本项目 | `validate-courses` + `score-course` |

```bash
node scripts/new-course.mjs mt_xxx --template=explain --renderer=vertical
python3 scripts/build.py && node scripts/validate-courses.mjs
node scripts/score-course.mjs mt_xxx
```

`score-course.mjs` 打十个维度：认知动作、分步揭示、概念反馈、迷思覆盖、图谱挂接、形成性评价、节奏、单文件、开场衔接、文案。低于 90 分不建议标 `reviewed`。它和校验脚本分工不同：校验管「对不对」，评分管「合不合理」。

### 质量门槛

- 数据校验、课件校验、教学研究测试三套并存，CI 全绿
- 引擎型课件按 content.steps 检查：类型合法、quiz 答案是数字、choice 答案在选项里、`misconception` 的键必须是错项（不能是答案）、vertical 算式成立、题目数与 meta.interactions 一致
- 产物必须零外链、含 `window.__GRAPH`
