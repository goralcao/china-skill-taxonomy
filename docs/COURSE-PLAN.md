## 二、为什么先修缺口这么大（一个不能绕开的约束）

| | 数量 |
|---|---|
| 现在就能开工（hard 先修全部已有课件） | **506** |
| 必须先垫上游才能开工 | **702** |

一句话：**hard 先修是 AND 语义——缺一条整个点就不能开工**，而已经做完的课件又
高度集中在链条下游，于是乘法效应把 ready 率压到了个位数。

### 拆解那 506 个：大部分是白送的

这 506 个里：

| 构成 | 数量 |
|---|---|
| 天生没有 hard 先修（源头点） | **492** |
| 因为相邻点做过了才解锁 | 14 |

也就是说，**506 里只有 14 个是我们"做出来"的**，其余 492 个本来就躺在那儿可开工。

对照组更能说明问题：随机抓 65 个点去做，平均也有 **500 个**可开工，中位 500。
**与现有排期几乎完全相同（1.0 倍）。** ready 的总量基本由图结构决定，不由选题决定。

### 根因：做的几乎全是下游

| 点的类型 | 全图 | 已做课件 | 覆盖率 |
|---|---|---|---|
| 源头（无 hard 先修） | 495 | 3 | **0.6%** |
| 非源头（有 hard 先修） | 778 | 62 | **8.0%** |

非源头点的直接先修**平均只做掉了 2.6%**。于是在 716 个非源头缺口里，
只有 14 个满足"所有 hard 先修都有课件"——**ready 率 2.0%**，其余 702 个全悬着。

这不是进度慢，是**顺序错了**：62 个非源头课件建在 3 个源头之上，地基是空的。

### 副产品：43 节已发布课件自己就有前置漏洞

`python3 scripts/plan-courses.py --audit-prereq` 查出来的，比排期更值得先看：

```
43 / 65 节已有课件，自己的 hard 先修还没做
```

意思是：孩子打开这节课时，它默认你已经会的东西，**根本没有课件可学**。举几个例子：

| 已发布的课 | 缺的先修 |
|---|---|
| 多位数乘一位数（`mt_mult-1digit`） | 7~9 的乘法口诀 |
| 面积的含义（`mt_area-intro`） | 厘米和米、平面图形的认识 |
| 分数的意义（`mt_frac-meaning`） | 平均分与除法的意义 |
| 朗读（`mt_read-aloud`） | 借助拼音识字和阅读 |
| 扩句（`mt_sent-extend`） | 完整句与句子成分、词语的归类与积累 |

补课时可以考虑先把这些洞填上——**填一个洞，同时修好几节课**。

### 瓶颈是集中的，不是发散的

好消息：卡住也不意味着要重头来做。

```
python3 scripts/plan-courses.py --bottleneck
瓶颈集合：562 个点卡着全部 1208 个缺口
```

1208 个缺口背后只有 **562 个真正的瓶颈点**。把这 562 个补上，其余全部就地解锁。
卡人最多的八个：

| 卡住下游数 | 瓶颈点 |
|---|---|
| 37 | 语文 1年级 声母的认读 |
| 36 | 数学 1年级 10 以内数的认识 |
| 35 | 语文 1年级 韵母与四声 |
| 34 | 数学 7年级 有理数的认识 |
| 34 | 语文 1年级 整体认读音节 |
| 34 | 语文 1年级 音节的拼读 |
| 34 | 英语 3年级 字母的名称与认读 |
| 33 | 语文 1年级 借助拼音识字和阅读 |

**一年级的拼音，卡着语文半壁江山。** 这八个点做出来，能解锁的下游比其他任何
八个点都多——排期器的"被依赖度"打分就是在自动追这个。

### 补洞优先模式（`--gap-first`）

既然 43 节已有课件悬空，先按常规队列从头刷就有点本末倒置。**补洞优先**模式把
"能修好几节已发布课件"作为最高权重：

```bash
python3 scripts/plan-courses.py --fix-gaps                # 看完整修补计划
python3 scripts/plan-courses.py --count 5 --gap-first     # 今晚的补洞清单
```

第一晚它会挑出这五个：

```
1. 平面图形的认识      补上可修好 5 节课
2. 厘米和米           补上可修好 3 节课
3. 默读               补上可修好 2 节课
4. 立体图形的认识      补上可修好 2 节课
5. 克与千克           补上可修好 1 节课
```

不需要手动切回常规模式——补洞项排在前面，随着洞被填上，这项计数自然衰减到 0，
队列自动回落成常规排期。

**收益曲线是典型的长尾**，按每晚 6000 字预算：

| 第几晚 | 还剩几节有漏洞 |
|---|---|
| 1 | 35（一晚修好 8 节） |
| 3 | 22 |
| 8 | 9 |
| 10 | 5 |
| 15 | 2 |
| 113 | 0 |

也就是说：**十晚左右就能把 43 节里的 38 节修好，收益的绝大部分在头两周。**

剩下拖到最后的只有 1~2 节，都是零起步学科或高中内容——最顽固的是物理的
「动量守恒定律」，缺的先修是「动量定理」，而物理 98 个知识点目前只有 1 节课件，
得把整条物理链垫起来才轮得到它。这类不必单独盯，跟着本学科的常规推进自然会过关。

`plan-courses.py` 每次都会重新扫描 `courses/` 目录，做完的点自动出列、下游自动解锁，
所以**每晚不需要人记住上次做到哪儿**。

## 三、排期打分依据

`plan-courses.py` 对每个可开工的点打分，四项依据：

| 依据 | 权重 | 理由 |
|---|---|---|
| **学段优先级** | 最高 | 小学 > 初中 > 高中。`--scope` 可切换为 `all`（均衡）或 `junior`（初中优先） |
| **被依赖度** | 高 | 有多少下游点把它当 hard 先修。做一节解锁一串，比做孤立点划算 |
| **模板成熟度** | 中 | 数学已积累 51 节，新开一节的成本远低于英语从 0 起第一节 |
| **同域连做** | 中 | 同一 domain 连着做，渲染器与讲法可复用，边际成本递减 |

队列头部的样子（第 1 晚）：

```
1. 数学 1年级 平面图形的认识     9 个下游依赖，做完可解锁 4 个
2. 数学 2年级 厘米和米          4 个下游依赖
3. 数学 1年级 10以内数的认识     4 个下游依赖，做完可解锁 5 个
4. 语文 2年级 默读             6 个下游依赖
5. 数学 1年级 立体图形的认识     3 个下游依赖
```

符合直觉：**先做垫在最底下、撑住最多东西的那几个**。

不能按"每晚 N 节"算——数学一节约 500 字，语文一节约 2400 字，差 5 倍。
所以按**每晚汉字预算**排，节数随学科浮动。学科平均字数由现有 61 节
`content.json` 实测得到。

|---|---|---|---|---|

## 五、风险（这些会让工期变长）

估算偏乐观的地方，得说在前面：

1. **新学科第一批要付"设计税"。** 英语、历史、生物、地理、化学、物理、道法、
   思政、技术、科学——十个学科目前零课件。第一批要设计该学科的课件骨架与步骤类型，
   就像 v0.43~v0.45 给语文做那三个版本（换骨架、加五个新渲染器）一样，
   单晚产能会掉到 2~3 节。排期器已给零起步学科打了负分让它们往后排，但迟早要碰。

2. **需要新渲染器的点会卡住。** 地理的经纬网、物理的受力图、生物的细胞结构、
   英语的发音——这些都要新画可视化。凡是牵到新渲染器的夜晚，产量减半。

3. **质量校验有返工。** `validate-courses.mjs` 与 `score-course.mjs` 目前是全程序列：
   65 节课件平均 97.6 分，新课件若低于 90 要重写。历史上每次新增步骤类型都要调试两三轮。

4. **1208 节意味着约 90 万字**教学内容。全部由模型生成，未经教师复核——
   这是项目 README 里已经写明、本项目一直承认的短板。做得多不等于做得对。

5. **拓扑存在"窄腰"。** 702 个点卡在上游。一旦上游某节点卡住，整条支线会停滞。
   排期器检测到无可用节点时会放宽到 soft 先修（连续 3 晚无进展则触发），但不保证彻底解开。

## 六、每晚执行流程（建议写进定时任务）

```
python3 scripts/plan-courses.py --count 5        # 1. 算出今晚做哪 5 节
# 2. 按 courses/<id>/content.json 的既有格式写课件，含 meta.json
python3 scripts/build.py                          # 3. 重建产物与题库
node scripts/validate-courses.mjs                 # 4. 课件校验，0 警告
node scripts/validate-questions.mjs               # 5. 题库校验
node scripts/score-course.mjs                     # 6. 质量评分，不低于 90
node tests/diagnose.test.mjs                      # 7. 引擎回归
git add -A && git commit                          # 8. 提交
git push origin main                              # 9. 推送
# 10. 生成一份夜间日报：做了哪几节、评分多少、解锁了多少下游、
#     剩余多少、预计还要几晚
```

**不自动发布线上**——每晚改线上站点，对已拿到分享链接的人风险太大。
早上看完日报再决定要不要发版。

## 七、相关文件

| 文件 | 作用 |
|---|---|
| `scripts/plan-courses.py` | 排期器。`--simulate` 算工期，`--count` 出今晚清单，`--json` 给机器读 |
| `scripts/validate-courses.mjs` | 课件校验（含互动/时长配比规则） |
| `scripts/score-course.mjs` | 单节教学质量评分 |
| `scripts/build.py` | 构建，同时重建 `data/questions.json` |

常用命令：

```bash
python3 scripts/plan-courses.py --count 5                  # 今晚做哪 5 节
python3 scripts/plan-courses.py --count 5 --gap-first      # 今晚做哪 5 节（先补已发布课件的洞）
python3 scripts/plan-courses.py --count 5 --max-grade 6    # 只考虑小学
python3 scripts/plan-courses.py --audit-prereq             # 已发布课件自身的前置漏洞
python3 scripts/plan-courses.py --bottleneck               # 卡人最多的瓶颈点
python3 scripts/plan-courses.py --fix-gaps                 # 漏洞修补计划
python3 scripts/plan-courses.py --simulate --budget 6000   # 全量工期模拟
python3 scripts/plan-courses.py --simulate --budget 6000 --scope all
```
