# 教学法：八条规则怎么落到 content.json

来自 math-viz-kit 的 `教学法规则库-v1`（读设计，不抄代码），每一条都翻成了这个仓库的字段和检查方式。

## V1 动态跃迁

**只做「静态讲不清、动态一秒懂」的知识点。**

判断：有没有「变与不变」的关系？学生的误区能不能被过程纠正？

落地：一节课只围绕一个动态关系。`vertical` 的进位、`perimeter` 的逐边累加、`fraction` 的逐份涂色，都是这个关系的载体。

检查：写不出「核心动态关系：____ → ____」就说明这节课不该做课件。

## V2 表征桥接

**一个操作，多个表征同时变。**

落地：竖式里点亮某一位，同时更新这一位的积、进位小字和下面的说明句；面积图里铺一格，计数和算式一起走。

检查：点一次演示，看有几处同时变化。只有一处，说明还是静态图。

## V3 分步揭示

**初始只给最小可理解单元，用户点了才展开，永远能重来。**

落地：`demo`（默认开）+ `CR.*.next()`；`reveal: 'all'` 只用于「先看一遍完整算法」的场合，且不能用在学习者还没见过的内容上。

检查：`score-course` 的「揭示」维度；`demo: false` 只允许两种情况——练习步骤、分数图（静态已给目标份数）。

## V4 信号聚焦

**颜色、箭头、高亮只指向一个关系。**

落地：一屏最多 3 种强调色；同一时刻只高亮一个对象；`warn: true` 的卡片最多一张。

检查：截图后眯眼看，第一眼落在哪。如果落在标题装饰上，删装饰。

## V5 操作先于符号

**先动手感受，再出公式。**

落地：`intro` 抛具体问题 → `vertical/geometry` 操作 → `text` 归纳（此时才写「所以 208×4=832」）→ `quiz` 应用。

检查：初始屏上有没有公式。有，就往后挪一步。

## V6 动作—数学一致

**操作方向和数学方向一致。**

落地：加法向右、减法向左；分段越多分数越小；参数变大图线变陡。`perimeter` 沿边顺时针走，不是随机点亮。

检查：用手比划一下操作，和数学量的方向对不对。

## V7 单一认知动作

**一页只承载一个动作。**

落地：`meta.cognitiveAction` 七选一（比较/分解/变换/逼近/累积/模拟/构造）。校验脚本要求 `reviewed` 必须填。

检查：`score-course` 的「动作」维度；填两个就拆课。

## V8 概念反馈

**反馈不说对错，说「你刚才发现了什么」。**

落地：`choice.misconception` 写每个错项的错因；`quiz.why` 写「错在哪」；`summary.points` 收敛成不变量。

检查：`score-course` 的「反馈」维度，要求错项全覆盖。

三种句式（第二人称，两句以内）：

- 不变量：「不管你怎么分，分母始终是 4。」
- 规律归纳：「被除数不变，除数越大，商越小。」
- 操作回顾：「你向右跳了 3 格，从 5 到 8，所以 5+3=8。」

反面：`✓ 回答正确！` `✗ 再想想`。

# 教学设计模板

借 k12-teacher-skills 的结构，压成五行，写进 `meta.json`。

## 目标

三条，动词可观察：

- 能算出 208×4，并说清十位上的 3 是哪来的
- 能判断 0 在中间时要不要乘
- 能用估算检查积是否合理

不要写「理解多位数乘一位数」——验收不了。

## 前测

从 `meta.prerequisites` 里挑最硬的一条，出 1 道 30 秒能答完的题。答错说明先修不够，这节课对他还太难。

放在第 1–2 步，不要放在最后当检测。

## 主线

```
情境（一个真实的错/一个真问题）
  → 操作（分步演示，学生跟着点）
  → 归纳（说出规律，不急着写公式）
  → 符号（此时才写算式）
  → 应用（2–3 道检测，含迷思错项）
```

## 形成性检测

- 2–3 题，覆盖「会不会」而不是「记没记住」
- 每题至少两个错项，每个错项写 `misconception`
- 错项要像真的：把 8/3 写成分母分子颠倒、把 5/16 写成母子都加

## 分层（可选）

写进 `summary.advice`，一两句：

- 基础层：「先只算不进位的，如 23×3」
- 进阶层：「试试 306×7，中间有两个 0」

不要写成「学有余力的同学可以……」——空话。
